# Sparkle integration roadmap

The app currently checks GitHub Releases at launch and toasts the user when a
new version is out (see [`src/updater.rs`](src/updater.rs)). It does **not**
download or self-install. This document is the path from there to a real
Sparkle-based silent in-place updater.

It's roughly a one-day spike that splits into three independent pieces:

## 1. Generate an Ed25519 keypair (one-time, on your dev machine)

```bash
brew install --cask sparkle           # ships the `generate_keys` tool
cd ~/.config/file-explorer
generate_keys
# Writes ed_private.key and ed_public.key. KEEP THE PRIVATE KEY OUT OF GIT.
```

The public key gets embedded into `Info.plist` (see step 3). The private key
signs every release tarball.

## 2. Host an appcast XML

Publish at e.g. `https://situmorang-com.github.io/file-explorer/appcast.xml`.
GitHub Pages on a `gh-pages` branch is the simplest hosting.

Sample appcast entry (one `<item>` per release):

```xml
<?xml version="1.0" encoding="utf-8"?>
<rss version="2.0" xmlns:sparkle="http://www.andymatuschak.org/xml-namespaces/sparkle">
  <channel>
    <title>File Explorer</title>
    <link>https://github.com/situmorang-com/file-explorer</link>
    <description>Latest releases</description>
    <language>en</language>

    <item>
      <title>v0.2.0</title>
      <pubDate>Mon, 02 Jun 2026 12:00:00 +0000</pubDate>
      <sparkle:version>0.2.0</sparkle:version>
      <sparkle:shortVersionString>0.2.0</sparkle:shortVersionString>
      <description><![CDATA[See <a href="https://github.com/situmorang-com/file-explorer/releases/tag/v0.2.0">release notes</a>.]]></description>
      <enclosure
        url="https://github.com/situmorang-com/file-explorer/releases/download/v0.2.0/file-explorer-v0.2.0-macos.zip"
        sparkle:edSignature="REPLACE_WITH_SIGNATURE_FROM_sign_update"
        length="REPLACE_WITH_BYTE_LENGTH"
        type="application/octet-stream" />
    </item>
  </channel>
</rss>
```

The signature comes from `sign_update file-explorer-v0.2.0-macos.zip`
(also from the Sparkle cask).

## 3. Embed Sparkle in the app

Three sub-steps:

### 3a. Add Sparkle.framework to the bundle

In `Cargo.toml` under `[package.metadata.bundle]`:

```toml
osx_frameworks = ["Sparkle"]
```

`cargo-bundle` will copy a Sparkle.framework from a system path or you can
download Sparkle from <https://sparkle-project.org/> and point at it via:

```toml
osx_extra_files = { "Sparkle.framework" = "vendor/Sparkle.framework" }
```

### 3b. Configure `Info.plist`

`cargo-bundle` lets you pass `osx_info_plist_exts`:

```toml
osx_info_plist_exts = { "vendor/sparkle-keys.plist" = "" }
```

with `vendor/sparkle-keys.plist`:

```xml
<dict>
  <key>SUFeedURL</key>
  <string>https://situmorang-com.github.io/file-explorer/appcast.xml</string>
  <key>SUPublicEDKey</key>
  <string>PASTE-PUBLIC-ED25519-KEY-HERE</string>
  <key>SUEnableAutomaticChecks</key>
  <true/>
  <key>SUScheduledCheckInterval</key>
  <integer>86400</integer>
</dict>
```

### 3c. Drive `SPUStandardUpdaterController` from Rust

Add to `Cargo.toml`:

```toml
objc2 = "0.5"
objc2-foundation = "0.2"
```

Then a thin shim like `src/sparkle.rs`:

```rust
use objc2::{class, msg_send, sel};
use objc2::runtime::AnyObject;

pub fn start() {
    unsafe {
        let cls: &AnyObject = msg_send![class!(SPUStandardUpdaterController), alloc];
        let _controller: *mut AnyObject = msg_send![
            cls,
            initWithStartingUpdater: true
            updaterDelegate: std::ptr::null::<AnyObject>()
            userDriverDelegate: std::ptr::null::<AnyObject>()
        ];
        // Controller is now retained by AppKit's framework
        // and handles scheduled checks + UI automatically.
    }
}
```

Call `sparkle::start()` from `main()` after `application().run` opens. Sparkle
takes it from there — schedules its own background checks, shows the macOS
sheet UI when an update is available, downloads, verifies the Ed25519
signature, prompts the user to relaunch.

## 4. Cut a release with the signature

The CI release workflow in `.github/workflows/release.yml` already attaches
`file-explorer-vX.Y.Z-macos.zip` to every tag. Append a step that runs
`sign_update` on the zip and writes the signature into a `signature.txt`
asset. Pull both into the appcast XML on the gh-pages branch (you can
automate that with a second workflow that commits to `gh-pages`).

## Why this isn't done already

The blocking pieces are all environment-level, not code:

- Ed25519 private key needs to be generated by you (and stored somewhere
  safe — losing it means every existing install loses the ability to
  update).
- GitHub Pages or another host must serve the appcast.
- Sparkle.framework binary must be vendored into the repo (it's ~3 MB).

The code shim itself is ~30 lines.
